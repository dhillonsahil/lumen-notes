# Lumen Notes Architecture

## Overview
Lumen Notes is a private, local-first desktop notes application built with Tauri v2, Rust 2024, React 19, TypeScript (strict), and SQLite. It provides a macOS Notes–style experience on Windows and Linux with zero external cloud dependencies, zero telemetry, and complete offline capability.

---

```

| React UI (TypeScript, CSS Tokens, Lucide Icons)                         |

|  - UI State (Current note, filter, search, active folder, dialogs)      |

                                    | Typed IPC (Invoke via @tauri-apps/api)
                                    v
+-------------------------------------------------------------------------+
| Tauri v2 Command Layer (src-tauri/src/commands)                         |
|  - Strict input validation & least privilege capabilities               |
|  - Error mapping (AppError -> IPC Serialized Result)                    |
|  - No SQL or business logic in handlers                                 |
+-------------------------------------------------------------------------+
                                    |
                                    v
+-------------------------------------------------------------------------+
| Application Service Layer (src-tauri/src/application)                   |
|  - NoteService: Lifecycle, revision checks, title fallback              |
|  - FolderService: Hierarchies, folder-cycle validation                  |
|  - AttachmentService: Scoped file paths, SHA-256 checks, 25MB limit     |
|  - ExchangeService: JSON archives, HTML/plain text export, safe import  |
|  - BackupService: Snapshots, rollback, SQLite VACUUM INTO snapshots     |
+-------------------------------------------------------------------------+
                                    |
                                    v
+-------------------------------------------------------------------------+
| Storage & Repository Layer (src-tauri/src/storage)                      |
|  - SQLite (rusqlite with bundled SQLite)                                |
|  - WAL mode, foreign keys, schema migrations                            |
|  - Thread-safe Mutex-managed repository connection                      |
|  - Managed attachment directory in platform AppData                     |
+-------------------------------------------------------------------------+
```

## Core Invariants and State Ownership

### 1. Document Format & Canonical Source
- The canonical document format is **versioned Tiptap JSON** (`document_json` with `document_version = 1`).
- Plain text (`plain_text`) is derived synchronously on document update and indexed for instantaneous search and note-list previews.
- HTML and Markdown are strictly export/import representations and are never stored as canonical source data.

### 2. Autosave Consistency & Monotonic Revisions
- Frontend user keystrokes are debounced with a 700ms timer.
- Every save payload carries `{ note_id, expected_revision, title, document_json, plain_text }`.
- The Rust storage layer enforces that `expected_revision == current_revision`. If mismatched (e.g. from an out-of-order save or concurrent session), the save is rejected with `AppError::RevisionConflict`.
- Explicit UI save states: `dirty` -> `saving` -> `saved` / `error`.
- When switching notes, any pending autosave timer is cancelled and immediately flushed synchronously to prevent edits leaking between documents.

### 3. Attachment Sandboxing & Security
- Attachment files are stored in the platform application data directory: `%LOCALAPPDATA%\com.lumennotes.app\attachments\<attachment_id>.<ext>`.
- Filenames on disk are strictly derived from generated UUIDs and sanitized alphanumeric extensions. User-supplied paths and directory traversals (`..`) are rejected.
- SHA-256 checksums are calculated over file contents and recorded in SQLite.
- File size is strictly enforced (maximum 25MB per attachment; empty files rejected).
- Attachments are served to the frontend via base64 data URLs generated by Tauri commands, completely isolating the host filesystem.

### 4. Exchange & Import Safety
- **Single Note Export**: Exportable to clean plain text (`.txt`), standalone styled HTML (`.html`), or complete JSON (`.json`).
- **Archive Export**: Bundles all active notes, tags, metadata, and base64-encoded attachment payloads into a versioned JSON archive (`lumen-notes-archive`).
- **Archive Import**:
  - Validates format headers and document JSON structures.
  - Generates a pre-import collision analysis comparing incoming IDs and titles against existing database records.
  - Provides explicit duplicate strategies:
    - `skip`: Omits conflicting notes while importing non-conflicting ones.
    - `overwrite`: Updates existing records with imported contents and advances revision counters.
    - `keep_both`: Generates fresh UUIDs and appends `(Imported)` to titles to guarantee no data loss.

### 5. Recovery & Snapshots
- **Emergency Crash Recovery Drafts**: In-flight changes are continuously mirrored to a local emergency key (`lumen_draft_<noteId>`). On unexpected process termination or reload, a recovery banner surfaces offering one-click draft restoration. Drafts are safely cleared once persistent database confirmation arrives.
- **Point-in-Time Snapshots**: Snapshots capture exact revisions of document JSON and titles in the SQLite `snapshots` table. The Snapshot History modal allows rolling back to any prior snapshot revision at will.
- **Consistent Backups**: SQLite `VACUUM INTO` creates a transactionally consistent copy of the database, ensuring WAL journals are fully checkpointed without relying on raw, potentially corrupted file copies.
